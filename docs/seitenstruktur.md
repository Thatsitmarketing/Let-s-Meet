# Seitenstruktur

Teil der Projektdokumentation, Einstieg und Regeln stehen in der [CLAUDE.md](../CLAUDE.md).

Öffentlich (einbettbar, `frame-ancestors *`):

| Pfad | Zweck |
| --- | --- |
| `/` | Zentrale Buchungsseite: erste öffentliche Terminart des Büros (Kostenfreies Strategiegespräch), ohne Auswahl der anderen Gespräche, Kalender mit direkt geöffnetem erstem freien Tag, links „Dein Termin“ mit Dauer, Ort und Beschreibung (ohne Logo). Bürofoto als Hintergrund, darüber mittig nur das weiße Logo That's it. Marketing (seit 2026-11-20 ohne „Lass uns reden.“ und ohne Text darunter, auf keiner Buchungsseite). Ziel: alles in einem Blickfeld (Karte endet bei 1440 × 820 knapp am Rand, bei 1920 × 960 komplett sichtbar). Jedes Gespräch hat nur seine eigene Seite, die Links pflegst du im Backoffice unter Terminarten (Link kopieren) und im Adminportal |
| `/{terminart}` | Dieselbe Seite für eine bestimmte Terminart, ohne Auswahl der anderen (Stand D1 2026-10-29: `/erstgespraech`, `/strategiegespraech-social-media`, `/strategiegespraech-recruiting`, `/strategiegespraech-webseite`, `/strategiegespraech-fotos-videos`, `/sichtbarkeits-check` inaktiv). `/erstgespraech` und `/strategiegespraech` leiten per 301 aufeinander, falls nur einer der beiden Slugs existiert (Homepage und Playbooks verlinken noch `/strategiegespraech`). Parameter: `embed=1`, `details=0`, `name`, `email`, `umbuchen={id}`. Vorbelegung ohne Serverkontakt über das Fragment `#name=&email=&telefon=&nachricht=&quelle=` (Schnittstelle zur Homepage, siehe unten) |
| `/{nutzer}`, `/{nutzer}/{terminart}` | Alte Personenlinks, 301 auf `/` bzw. `/{terminart}` (Parameter bleiben erhalten) |
| `/termin/{id}` | Bestätigung und Verwaltung für den Gast (Kalender, Umbuchen, Absagen) |
| `/termin/{id}/absagen` | Absage mit optionalem Grund |
| `/termin/{id}/kalender.ics` | Kalenderdatei |
| `/embed.js` | Widget Skript (Inline, Popup Button, Popup Link) |
| `/api/slots`, `/api/buchen` | Slots abrufen, Buchung anlegen |
| `/api/cron` | Cron manuell auslösen (Bearer `CRON_SECRET`) |
| `/playbook/{id}` | Persönliche Playbook Seite aus der Mail der Landingpages: Flipbook, PDF Download, Knopf zum passenden Gespräch. 14 Tage gültig (seit 2026-10-29, vorher 30, Frist hervorgehoben im orangenen Kasten unter der Einleitung), danach Hinweis mit „Playbook neu anfordern“ (Landingpage). `noindex`, nicht einbettbar, `no-store`. Seit 2026-10-29 ohne Let's Meet Bezug: im Kopf das schwarze Logo That's it. Marketing (`logo-schwarz.webp`, Link auf thatsit.marketing), Browsertitel „… \| That's it. Marketing“ (Eigenschaft `marke="thatsit"` an `Oeffentlich.astro` und `Basis.astro`) |
| `/playbook/{id}/pdf`, `/playbook/{id}/seite/{nr}`, `/playbook/{id}/gesehen` | PDF (zählt Downloads), Seitenbild des Flipbooks, Meldung „geöffnet“ (POST aus dem Browser nach 1,5 Sekunden sichtbar, damit Linkprüfungen der Mailprogramme nicht zählen). Nur mit gültigem Link |
| `/api/playbook/anfordern` | Schnittstelle der vier Playbook Landingpages, POST JSON mit Bearer `PLAYBOOK_SCHLUESSEL` (siehe „Playbooks“ unten) |
| `/api/anfrage` | Schnittstelle für Landingpages ohne Playbook (seit 2026-11-16: Website Entwurf Funnel), POST JSON mit Bearer `ANFRAGE_SCHLUESSEL` (siehe „Anfragen“ unten) |
| `/playbook-dateien/*` | Gesperrt (404), siehe „Playbooks“ |
| `/api/google/rueckruf` | OAuth Rückruf (liegt bewusst außerhalb von `/api/app`, siehe Formulare) |
| `/auth/switch?to=<id>` | Tool Wechsel, Ausgang (seit 2026-11-24): nur mit Backoffice Sitzung, stellt ein 60 Sekunden gültiges Token aus und leitet per 302 ins andere Tool. Ohne 2FA Beleg der Sitzung per 302 zum Lead System (dort Anmeldung mit 2FA), ohne Anmeldung eine kurze Seite (401). Siehe „Tool Wechsel (Link)“ |
| `/auth/switch/in?token=` | Tool Wechsel, Eingang: öffentlich, prüft das Token und startet die Sitzung, Antwort ist eine Seite mit meta refresh (kein 302). Ohne `LINK_SECRET` antworten beide Routen mit 404 |

Backoffice (`/app`, geschützt durch Middleware, `noindex`, `X-Frame-Options: DENY`):

| Pfad | Zweck |
| --- | --- |
| `/app/login`, `/app/setup`, `/app/abmelden` | Anmeldung, Ersteinrichtung, Abmelden |
| `/app/terminarten` | Übersicht als Karten in 4 Spalten (ab 1200px, ab 700px 2, darunter 1) mit Kurztext aus der Beschreibung (3 Zeilen), getrennt in die Abschnitte „Aktiv“ oben und „Nicht aktiv“ darunter (je mit Anzahl, ausgeschaltete rutschen automatisch nach unten), aktiv schalten, Link kopieren, QR-Code, duplizieren (Löschen nur im Editor). Seit 2026-10-29 stehen Bearbeiten und Duplizieren oben rechts neben dem Schalter, „Geheim“ in der Zeile mit Dauer und Ort, unten „Link kopieren“ und „QR-Code“ (nebeneinander oder je eine volle Zeile) |
| `/app/terminarten/neu`, `/app/terminarten/{id}` | Oben Link kopieren, QR-Code, Ansehen. Editor: Titel, Link, Dauer, Farbe, Ort, Unterlagen zur Vorbereitung, Planung, Fragen, Nach der Buchung (Zusatztext, Weiterleitung), „Benachrichtigungen und Arbeitsabläufe“ (Haken je Arbeitsablauf = gilt für diese Terminart, Bearbeiten Stift, „Neuer Arbeitsablauf“ mit `?terminart=`), Sichtbarkeit, ganz unten „Terminart löschen“ mit Rückfrage. Duplizieren übernimmt die Zuordnung der Arbeitsabläufe |
| `/api/app/terminarten/{id}/qr` | QR-Code zum Link der Terminart, `?format=png` (Standard, rund 1.200 Pixel, Graustufen) oder `svg`, mit `&download=1` als Datei `qr-code-{slug}.png` bzw. `.svg`. Kodiert immer `SITE_URL/{slug}` (feste Domain, nicht die Adresse im Browser), Fehlerkorrektur M, Ruhezone 4 Module, Schwarz `#0E0E0E` auf Weiß. Nur angemeldet (401) |
| `/app/termine` | Standard Tab Kalender (Woche oder Monat, daneben „Als Nächstes“ mit den nächsten 6 Einträgen aus Buchungen und blockierenden Google Terminen, ohne Briefkasten und „Verfügbar“), dazu Listen Anstehend, Vergangen, Abgesagt mit Suche und Zeitraum, Team Ansicht für Admins, CSV Export. Parameter: `ansicht`, `kal=woche\|monat`, `datum`, `wer=team` |
| `/app/termine/{id}` | Details, Verlauf der Arbeitsabläufe (gesendet, entfallen, Fehler), interne Notiz, nicht erschienen (ab Terminbeginn markierbar, löst den Arbeitsablauf aus), „Nicht erschienen und sperren“ (ausqualifizieren: ohne Mail, Kontakt gesperrt, „Sperre aufheben“), Absagen, Umbuchungslink |
| `/app/kontakte` | Kontaktbuch des Büros als Tabelle wie bei Calendly: Name (darunter Pille „Playbook angefordert“, „geöffnet“ oder „geladen“), E Mail, Telefon, Unternehmen, Datum des letzten und des nächsten Meetings (mit Uhrzeit). Suche, Filter (`filter=anstehend\|neu\|ohne`: mit anstehendem Meeting, neu in 30 Tagen, kein Meeting in den nächsten 30 Tagen), Sortierung über die Spaltenköpfe (`sort=name\|naechstes`, Standard letztes Meeting), 100 pro Seite, unter 900px als Karten. Unten CSV Import, oben CSV Export (`/api/app/kontakte.csv`) |
| `/app/kontakte/neu`, `/app/kontakte/{id}` | Kontakt anlegen (Vorbelegung `?name=&email=`) bzw. bearbeiten: Überblick mit letztem und nächstem Meeting und Herkunft, Kontaktdaten mit interner Notiz, Mail und Anruf, Liste aller Meetings (Buchungen und Google Termine), Karte „Buchung“ (Buchung sperren oder Sperre aufheben), Abschnitt „Playbooks“ (jede Anfrage mit den Angaben aus dem Formular, geöffnet und PDF geladen, Link um 14 Tage verlängern oder sperren), „Termin buchen“ öffnet `/` mit vorausgefülltem Formular über das Fragment, „Kontakt entfernen“ mit Rückfrage |
| `/app/playbook-leads` | Leadliste der Playbook Anfragen (Menüpunkt „Playbook Leads“ unter Kontakte): Reiter je Playbook mit Anzahl und Farbpunkt (Website blau, Social Media orange, Recruiting grün, Gastro rot), Filter `stand=angefordert\|geoeffnet\|geladen`, Suche, eine Zeile je Anfrage mit Name (darunter Unternehmen), Playbook, E Mail (eigene Spalte, Mailto Link), Telefon, Angaben (Antworten aus dem Formular der Landingpage, eine Zeile je Frage, seit 2026-11-16 Website und Teamgröße), Angefordert, Geöffnet (Anzahl, zuletzt), PDF geladen (Anzahl, zuletzt), Link (gültig bis, abgelaufen, gesperrt, „Alter Downloadlink“). Name führt in den Kontakt. Spalten brechen nicht um, die Tabelle scrollt seitlich wie im CRM, die Spalte Name bleibt dabei links stehen. CSV Export `/api/app/playbook-leads.csv` mit denselben Filtern. Unter 1000px Karten. Oben Knopf „Aktualisieren“ mit „Stand HH:MM Uhr“: holt die Seite im Hintergrund und tauscht nur die Liste (`data-lead-bereich`), Filter und Suche bleiben, ohne JavaScript ein normaler Link. Kehrt man nach über einer Minute in den Tab zurück, aktualisiert die Liste von selbst. Abgelaufene Sitzung führt zur Anmeldung |
| `/app/anfragen` | Anfragen über Landingpages ohne Playbook (Menüpunkt „Anfragen“ unter Playbook Leads, seit 2026-11-16): Reiter je Quelle (bisher nur Website Entwurf, Farbpunkt blau), Suche, eine Zeile je Anfrage mit Name (darunter Unternehmen), Quelle (darunter „Wiederholte Anfrage“, wenn die Landingpage dieselbe E Mail oder Nummer in 30 Tagen schon hatte), E Mail, Telefon, Angaben (Antworten aus dem Funnel), Eingegangen. Name führt in den Kontakt (`#anfragen`). CSV Export `/api/app/anfragen.csv`. Aufbau wie die Leadliste, unter 1000px Karten |
| `/app/arbeitsablaeufe` | Arbeitsabläufe wie bei Calendly als Tabelle (unter 1000px Karten): Aktiv Schalter, Name, Gilt für (Terminarten mit Farbpunkt oder „Alle Terminarten, auch neue“), Wenn das passiert, Das tun, Anzahl gesendet in 30 Tagen, Bearbeiten, Duplizieren |
| `/app/arbeitsablaeufe/neu`, `/app/arbeitsablaeufe/{id}` | Editor: Name, Aktiv, Auslöser mit Zeitpunkt, Aktion (Mail an Gast, Büro oder bis zu fünf andere Adressen), Gilt für (alle oder einzelne Terminarten), Betreff, Überschrift, Text mit Platzhaltern (Klick fügt ein), Vorschlag je Auslöser laden, „Speichern und Testmail“ (Beispieldaten an die angemeldete Person), Duplizieren, Löschen mit Rückfrage. `?terminart=` ordnet direkt zu und führt zurück in den Terminart Editor |
| `/app/termine/google/{eventId}` | Google Termin live aus Google: Zeit, Ort, Meet Link, Teilnehmende mit Antwort, Beschreibung (HTML als Text). Bearbeiten (Titel, Datum, Beginn, Ende, Ort, Beschreibung, „Verfügbar“), Löschen, Teilnehmende auf Wunsch per Mail informieren (`sendUpdates`). Termine anderer Organisatoren nur ansehen oder aus dem Kalender entfernen, wiederkehrende Termine ändern nur diesen einen Termin. Jede Änderung geht sofort in `google_termine` |
| `/app/verfuegbarkeit` | Wochenzeiten mit mehreren Zeiträumen pro Tag (Zeitfelder passen sich der Spaltenbreite an, das X zum Entfernen steht immer vor der Spalte mit Plus und Kopieren), Zeitzone, Kalender mit Live Vorschau ungespeicherter Wochenzeiten, Ausnahmen für Tage oder Zeiträume (Klick auf einen Tag im Kalender trägt das Datum ein, `?ausnahme=`) |
| `/app/einbetten` | Codegenerator nur für das Inline Widget, mit Live Vorschau |
| `/app/integrationen` | Oben Status aller Dienste mit Logos (Google, Resend, Turnstile, Webhook, Cron, `DiensteStatus.astro`), darunter Einrichtung von Google Kalender (Stand des letzten Abgleichs, Fehlergrund, Knopf „Jetzt abgleichen“) und Webhook mit HMAC Signatur |
| `/app/einstellungen` | Admins: zentrale Buchungsseite (Name des Büros als Gastgeber; das Feld „Text unter Lass uns reden.“ ist seit 2026-11-20 entfernt, die Spalte `nutzer.begruessung` wird nicht mehr gelesen). Alle: eigenes Profil und Passwort. Admins zusätzlich unten das Adminportal (`Adminportal.astro`: alle Gespräche mit Homepage Zuordnung `HOMEPAGE`, Link, QR-Code als Symbol, Verweise auf Werkzeuge) und ganz unten die Vorschau der Buchungsseite (iframe `/?embed=1`) |
| `/app/werkzeuge` | Leitet per 301 auf `/app/einstellungen` (Adminportal ist dort eingebaut) |
| `/app/whatsapp/vorlagen` | Nur Admins (Knopf „Vorlagen“ auf `/app/whatsapp`, seit 2026-11-21): die vier Nachrichtenvorlagen des Bots mit Vorschau als Chatblase, Kategorie, Beispielwerten und Status bei Meta (Freigegeben, In Prüfung, Abgelehnt mit Grund, Nicht eingereicht), „Alle vier Vorlagen einreichen“ beziehungsweise „Diese Vorlage einreichen“, Hinweis wenn der Text bei Meta vom Code abweicht. Konto über `WHATSAPP_WABA_ID`, im Feld überschreibbar. Logik in `src/lib/whatsapp/vorlagen.ts` |
| `/app/team` | Nur Admins: Mitglieder anlegen, Rolle, deaktivieren, Passwort setzen. Das Büro steht oben mit Badge „Büro, zentrale Buchung“ und lässt sich nicht deaktivieren |
